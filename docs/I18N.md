# Español e English

## Uso

En **Ajustes → Idioma**, seleccionar **Español** o **English** y pulsar
**Guardar preferencias**. En inglés: **Settings → Language → Save preferences**.
La interfaz cambia al confirmar el servidor, sin recargar la página. Español
sigue siendo el idioma inicial para todas las cuentas existentes y nuevas.

La preferencia se conserva por usuario en SQLite, se incluye en sesión/estado y
exportación JSON, y se aplica en otros navegadores al iniciar sesión. El acceso
recuerda además el último idioma de ese navegador; ese pequeño valor local es
solo una preferencia de presentación, no almacena datos de cuenta ni tareas.

Se traducen navegación, siete secciones, estados y prioridades, filtros, editor,
captura, etiquetas accesibles, ayudas, mensajes y fechas formateadas. Títulos,
proyectos, descripciones, notas, etiquetas e histórico escrito por el usuario
permanecen intactos. No se cambia el calendario, zona horaria, inicio de semana,
valores ISO ni códigos de estado/prioridad. Los controles nativos de calendario
siguen dependiendo también del idioma del navegador/sistema operativo.

## Implementación

- `src/i18n.ts`: catálogo, suscripción de React, locale, interpolación numérica y
  presentación de errores conocidos de API. La respuesta autenticada del servidor
  es la autoridad de la preferencia; no se utilizan servicios externos.
- `src/locales/en.json`: catálogo inglés centralizado. Español utiliza las claves
  fuente; el contenido del usuario no pasa por la función de traducción.
- `users.language`: `es`/`en`, validado tanto por la API como por SQLite. La
  actualización opera únicamente sobre la cuenta autenticada.
- `migrations/002_language.sql`: columna aditiva con `es` predeterminado. Arranque
  transaccional e idempotente; preserva identificadores, relaciones, eventos,
  preferencias y credenciales existentes. No se crea ni sustituye una demo.
- Recuperación: acepta exactamente esquemas 001 y 002. Verificar/copiar/restaurar
  no aplica migraciones a la fuente; el archivo restaurado antiguo migra al abrirse
  con esta versión. Una copia nueva conserva idioma por usuario.

No se añade ninguna dependencia ni se migra la arquitectura. El formato JSON
exportado conserva su versión de estructura; `user.language` es un campo aditivo.
CSV conserva sus códigos canónicos para evitar cambios en intercambios de datos.

Para nuevas etiquetas, añadir la clave española al catálogo inglés y envolver
solo el texto de interfaz con `t` (alias `tr` en App). Utilizar `{0}`, `{1}`, etc.
para interpolaciones. Para agregar un tercer idioma habrá que ampliar el catálogo,
contrato, validación y constraint SQLite con una migración compatible; no basta
con añadir una opción sin persistencia.

## Pruebas

```sh
npm test
npm run build
npm run test:e2e
```

La nueva cobertura incluye traducción/interpolación, migración íntegra desde 001,
validación y aislamiento por cuenta, exportación, backups antiguos, interfaz en
las siete secciones, idioma de documento y fechas, estado/prioridad, captura
móvil, persistencia entre recargas, logout/login y navegador nuevo. Una tarea
ficticia titulada literalmente «Pendiente» sigue llamándose así en inglés.

Las pruebas usan únicamente bases temporales y cuentas ficticias. No se abre la
base existente del propietario. La nueva cuenta exclusiva del fixture E2E evita
alterar los límites de login reales para ejecutar las pruebas.

## Actualizar Codespaces

En la rama `dev/focus-hub-v1.1-ux-readiness`, con cambios locales guardados:

```sh
git fetch origin dev/focus-hub-v1.1-ux-readiness:refs/remotes/origin/dev/focus-hub-v1.1-ux-readiness
git merge --ff-only origin/dev/focus-hub-v1.1-ux-readiness
node .devcontainer/service.mjs stop
bash .devcontainer/start.sh
```

El cambio incluye backend y migración, por lo que esta vez sí requiere reiniciar
el servidor. No necesita reconstruir el contenedor ni instalar nuevas dependencias.
La migración se aplica automáticamente; credenciales y datos se conservan. Seguir
usando **3000 privado**. Ver CODESPACES.md si aún no se está en esa rama.

## Resultado de integración

- Compilación TypeScript/Vite correcta.
- `npm test`: **56/56**, cero fallos y cero omitidas.
- `npm run test:e2e`: **15/15**, Chromium, 1,2 minutos. Incluye toda la regresión
  v1.1 y el nuevo recorrido bilingüe.
- Sin dependencias nuevas, publicación de servicios o cambios en la privacidad.
- Cuatro subagentes reales: persistencia/recuperación, componentes, catálogo y QA;
  coordinador responsable de contratos, integración, documentación y validación.

La revisión final en inglés añadió **42 comprobaciones responsive** (siete
secciones × tres anchuras × dos temas), sin overflow de página. El recorrido
bilingüe ampliado pasó de nuevo tras completar las etiquetas en mayúsculas y
el contraste de las ayudas de Ajustes.
